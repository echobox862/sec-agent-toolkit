# 脱敏与合规说明

这份文档说明三件事：仓库里哪些信息被处理过、用什么规则判断、还剩哪些需要人工知悉的风险。

## 一、原则

**能写代号的不用真名，能用保留地址的不用真地址。** 目标写 TARGET-A，网段写 10.0.0.0/8、192.168.0.0/16、127.0.0.1，账号写「用户A」「用户B」，口令写占位符。

**不入库的东西，一次都不提交。** 原始报告、抓包、截图、扫描结果、字典文件、凭据，全部不进版本库。仓库里只有方法和合成数据。

**测试数据也不放过。** 假手机号、假密钥看着像真的，一样会被扫描器命中，也会被读者当成可用凭据。所以测试里的敏感样例在运行时拼接，源码不出现字面量。

## 二、分级规则

| 级别 | 命中对象 | 处理 |
| --- | --- | --- |
| high | 公网 IP、域名、邮箱、手机号、AWS/GitHub/Slack 令牌、私钥、JWT、脚本文件内容、命令执行调用、绝对路径 | 阻断提交 |
| medium | 私网 IP、回环地址、Windows/Unix 用户目录 | 逐条确认后放行 |
| info | webshell 工具名、靶场平台名、缺少授权说明 | 提示，不阻断 |

两处例外：

- **RFC 5737 文档地址**（192.0.2.0/24、198.51.100.0/24、203.0.113.0/24）不算泄露。这些段专门留给文档举例，写进仓库是规范做法。
- **邮箱里的域名不重复报。** 扫描邮箱时跳过 `@` 后面的域名，避免一次泄露被算成两条。

## 三、扫描对象与方法

**对象**：仓库内全部文本文件，共 35 个（`.md`、`.py`、`.toml`、`.txt`、`.gitignore`），不含二进制与 `__pycache__`。

**方法**：两套规则交叉验证。

1. `skills/web-vuln-writeup/scripts/check_redlines.py` —— 面向笔记的发布前检查，逐行扫描。
2. `mcp/report-lint` 的 `scan_sensitive` —— 面向报告交付的检查，按文档顺序抽取后扫描。

两套规则的正则集独立维护，一套漏了的另一套能补上。这也是为什么仓库里有两个相似的检查器：场景不同，容错要求不同。

## 四、扫描结果

```

info：11
```

**high 为 0。** 初版扫描曾报出 4 项，全在 `mcp/report-lint/tests/test_rules.py` 的测试用例里：一个假邮箱、一个假手机号、一个格式正确的假 AWS key、一个假 Windows 路径。虽然都不是真实数据，但字形像真的，仍然改成了运行时拼接。改后归零。

**medium 26 项的构成**：

| 类型 | 位置 | 说明 |
| --- | --- | --- |
| 保留网段示例 | `LEGAL.md`、`references/redlines.md`、`tools/port_scan.py` | 说明「目标统一用 10.0.0.0/8、192.168.0.0/16」时列出，属规则文本 |
| 回环地址 | 两个 MCP 的 README 与测试 | 示例调用与单元测试，127.0.0.1 不指向任何真实系统 |
| 私网测试地址 | `tests/test_tools.py`、`tests/test_rules.py` | 验证「私网放行」分支所需 |

这些地址没有一个是真实环境里取来的，全部是为说明规则或验证分支而写。

**info 11 项**：webshell 工具名与靶场平台名，集中在 `check_redlines.py` 的检测规则表和 `redlines.md` 的红线说明里。它们是「列举不能上传什么」的文本，不是工具本体，也不是可执行内容。

## 六、遗留风险

**medium 项需要人工知悉。** 26 项都不是泄露，但读者可能把示例地址当成真实目标。文档里已注明来源，仍建议在引用时保留上下文。

**工具名提及仍是双刃剑。** 红线说明必须点名工具才能讲清边界，但搜索命中的概率会增加。当前处理方式是只提名字，不附链接、不附安装方式、不附配置。

**Git 历史不可撤回。** 如果后续误提交敏感内容，普通 commit 无法彻底清除，需要改写历史并强推。所以每次提交前跑一遍扫描，比事后补救便宜得多。

**自动化规则有盲区。** 正则抓不到图片里的文字、抓不到编码后的内容、抓不到语义上的暗示。人工复核仍然必要，尤其涉及截图和示例数据时。

## 七、复检方式

```bash
# 单篇笔记
python skills/web-vuln-writeup/scripts/check_redlines.py <文件.md>

# 单份报告
report-lint scan <报告.docx>

# 整仓库（在仓库根目录执行）
python - <<'PY'
import pathlib, sys
sys.path.insert(0, "skills/web-vuln-writeup/scripts")
from check_redlines import scan
for p in pathlib.Path(".").rglob("*"):
    if p.is_file() and p.suffix.lower() in {".md", ".py", ".toml", ".txt"}:
        for h in scan(p.read_text(encoding="utf-8", errors="replace")):
            if h["severity"] == "high":
                print(p, h["line"], h["type"], h["value"])
PY
```

最后一段脚本没有输出，就说明没有 high 项。
