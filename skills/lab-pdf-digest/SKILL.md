# 讲义精讲

## When to Use

- 拿到一整套培训材料（十几份 PDF、几百页），要从第一页读到最后一页不现实。
- 材料是 PPT 导出的，一页只有几行字加截图，直接提文本会丢信息。
- 需要判断教材里的结论今天还成不成立。

不适用：单篇论文、需要批判性评估的研究材料。那类内容的价值在论证链条，用四栏拆会拆散。

## Prerequisites

- 能按页读取 PDF：文本层可用就走文本，不可用就走读图。
- 知道这批材料大概的主题范围，否则排不出学习顺序。
- 有可核对的公开资料（厂商文档、版本说明），用于写勘误。没有依据的怀疑不要写成勘误。

## Workflow

1. **先摸模板，再逐页读。** 同一批材料通常共用一套 PPT 模板。先看三份，确认结构：封面、目录、分节封面、正文、结束页。这一步能省掉大量无效阅读。

2. **跳过没有内容的页。** 分节封面（PART 01 这类）只有标题，跳过。目录页只用来建立索引。

3. **合并连续截图。** 同一节里连续几页常常是同一个操作的分步截图，正文文字往往只在第一页。把它们当成一段，不要拆成几个知识点。

4. **按四栏填。** 页段、内容、技术要点、原理与设计含义。第三栏记命令、函数、参数；第四栏解释为什么这样设计。只有前两栏的笔记，过两周就只剩截图。

5. **标勘误。** 发现结论过时或不准确，在该条末尾打 ⚠️，写清版本依据。例如「教材写直接写文件即可，但 MySQL 8 默认 `secure_file_priv` 为 NULL，这条路走不通」。没有版本依据的，标「待核实」，不要写成结论。

6. **出索引。** 按篇生成 md，加一份总索引：篇名、页数、层级（地基/工具/攻击/工具化/实战）。再给一条学习顺序，说明为什么先读哪几篇。

7. **回读校验。** 抽三篇对照原 PDF，确认页段号没有错位、截图描述与页面一致。

## Verification

- 每篇的页段号能对上原 PDF。
- 四栏齐全，第四栏不是对第三栏的复述。
- 勘误条目标了依据（版本号、参数名、文档链接），或明确写「待核实」。
- 总索引覆盖全部文件，页数合计与原批次一致。
- 读图补齐的部分做了标注，没有把推测写成原文。

## 这个技能不做的事

- 不做 OCR 全文转录。逐字抄一遍没有价值，要的是结构和判断。
- 不把教材结论直接当标准答案。教材有版本滞后，核实是必要步骤。
- 不在没有依据时写勘误。怀疑可以标「待核实」，不能写成定论。
