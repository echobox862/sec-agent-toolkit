# 精讲方法

## 一、四栏体例

每条按四栏写，缺一栏就退化成流水账。

| 栏目 | 写什么 | 判断标准 |
| --- | --- | --- |
| 页段 | 页码范围，对应原 PDF | 能据此翻回原文 |
| 内容 | 这几页在讲什么 | 不看原文也能回忆起主题 |
| 技术要点 | 命令、函数、参数、概念 | 可以直接照着敲 |
| 原理与设计含义 | 为什么这样设计、背后是什么机制 | 回答「为什么」，不是复述「是什么」 |

第三栏和第四栏最容易混。第三栏是「怎么做」，第四栏是「为什么这么做」。只有第三栏，面试追问一层就断。

## 二、模板规律

成套讲义多数是同一套 PPT 模板，结构高度固定：

```
封面（1 页）
目录（1 页）
PART 01 …（分节封面 1 页 + 内容 N 页）
…
结束页（1 页）
```

两条读图规律：

1. 「PART 0X」页没有内容，只是分节封面，跳过。
2. 同一节里连续多页常常是同一操作的分步截图，正文文字往往只在第一页给出。看到连续几页只有一两句话，它们是同一段的延续，不要当成独立知识点。

## 三、文本层不可用怎么办

部分 PDF 的字体子集缺 ToUnicode 映射，直接复制文本会得到乱码，但页面显示正常。处理顺序：

1. 先试文本提取，出现大面积乱码或替换字符，判定为不可用。
2. 改用按页读图，把页面上的文字读出来，再按四栏整理。
3. 在笔记里标注「本段由读图补齐」，不要把读图结果说成原文摘录。

判断依据要留：哪些篇是文本提取、哪些是读图，索引里写清楚。后续有人核对时知道从哪查。

## 四、勘误怎么写

格式：`⚠️ 勘误：<教材说法> 在 <条件/版本> 下不成立，应为 <正确说法>。依据：<版本号、参数默认值、官方文档>。`

例子：

> ⚠️ 勘误：教材写「拿到数据库权限后可直接写文件拿 shell」。MySQL 8 默认 `secure_file_priv` 为 NULL，`into outfile` 会被拒绝，需该参数指向可写目录且有 FILE 权限。依据：MySQL 8.0 官方文档 secure_file_priv 默认值。

三条纪律：

- 有依据才写「勘误」，没依据写「待核实」。
- 只写结论差异，不写「教材错了」这种评价。
- 涉及版本的一律带版本号，不带版本的结论过一年就不成立。

## 五、索引与学习顺序

索引表至少四列：篇名、页数、层级、一句话内容。层级建议分五档：地基（环境、协议、语言）、工具、攻击手法、工具化、实战。

学习顺序不要按文件顺序排，按依赖排。地基不打，后面的工具化内容看不懂；工具不熟，攻击手法只能照抄步骤。

## 六、验收

抽三篇回读，检查四件事：

1. 页段号对得上。
2. 截图描述与页面一致。
3. 第四栏不是第三栏的复述。
4. 勘误有依据或标了待核实。
