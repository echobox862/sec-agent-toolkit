# 发布红线与脱敏规则

公开笔记之前逐条过。这份清单来自实际踩过的坑，不是形式条款。

## 一、不能发布的内容

| 类别 | 具体内容 | 原因 |
| --- | --- | --- |
| 武器化工具 | webshell 管理器本体、安装包、连接配置 | 会被平台判定为恶意内容，也不是自己的作品 |
| 真实目标 | IP、域名、URL、账号、手机号、Cookie、Token | 泄露他人信息，可能违反授权协议 |
| 可用载荷 | 能直接打通的完整注入语句、上传后门的完整文件内容 | 展示原理用最小验证即可 |
| 凭据 | 密码、密钥、`.env`、扫描结果文件 | 一旦推送就很难彻底回收 |
| 教材原文 | 培训手册整段搬运 | 那是平台材料，不是自己的产出 |

## 二、必须替换的内容

| 原始信息 | 替换为 |
| --- | --- |
| 目标域名、IP | TARGET-A、10.0.0.0/8 段地址 |
| 账号、手机号 | 用户A、用户B |
| 口令 | `<口令>`、`P@ssw0rd` 这类明显占位 |
| 时间戳、订单号 | 保留格式，数值泛化 |
| 绝对路径 | `<安装目录>`、相对路径 |
| 载荷原文 | 只写类型名，如「布尔盲注条件」「双写变形」 |

## 三、文字里可以出现、但不能附带文件的内容

工具名（蚁剑、Burp、sqlmap）可以在叙述中出现，说明用了什么工具是正常的技术描述。不允许的是上传工具本体、安装包、配置文件或可直接运行的脚本。

判断标准：读的人能不能照着这段文字直接把目标打穿。能，就是越界；只能理解原理，是合适的粒度。

## 四、每篇笔记必须有的两句话

1. 「仅用于授权测试与安全学习」。
2. 实验环境说明，例如「2025 年 6–7 月授权靶场环境，目标信息已脱敏」。

这两句不是免责形式，是边界声明。面试官看到会知道你清楚红线在哪。

## 五、检查脚本怎么用

```bash
python scripts/check_redlines.py writeups/01-file-upload.md
```

- 退出码 0：没有 high 项，可以发布。
- 退出码 1：有 high 项，必须处理。
- 退出码 2：文件读不到或参数不对。

high 项包括公网 IP、域名、邮箱、手机号、密钥、绝对路径、可执行载荷特征。工具名这类提示归入 info，只提醒不阻断。
