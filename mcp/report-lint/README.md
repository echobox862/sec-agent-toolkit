# report-lint

渗透测试报告交付前自检。查四件事：结构齐不齐、编号连不连续、有没有没脱敏的信息、对外声明能不能在报告里找到对应。

只读，不改文件，不判断漏洞真伪。

## 为什么做这个

起因是一次真实的交付事故：对外材料写「报告含整改建议、按风险等级整理」，把 14 页报告调出来逐页核对，"整改""建议""风险等级"三个词在正文里各出现 0 次。

这类问题人工通读容易漏，脚本跑一遍就出来。所以把检查做成工具，交付前跑一次。

## 安装

```bash
cd mcp/report-lint
pip install -e .
# 需要读 PDF 时
pip install -e ".[pdf]"
```

只依赖 `python-docx`；PDF 支持是可选的，靠 `pymupdf`。

## 命令行用法

```bash
# 完整检查
report-lint lint 报告.docx

# 顺带核对对外声明
report-lint lint 报告.docx --claims "22 条" "高危 6" --json

# 只扫敏感信息
report-lint scan 报告.docx
```

退出码：0 通过，1 有问题，2 文件读不了。

## 三个工具

| 工具 | 作用 | 返回 |
| --- | --- | --- |
| `lint_report` | 结构、编号、脱敏、声明一次查完 | 完整报告 + verdict |
| `scan_sensitive` | 只扫敏感信息 | 命中列表，按 high/medium 分级 |
| `check_claims` | 核对声明是否能在正文找到 | 每条声明的 ok/conflict |

## 查什么

**结构四维度**，每条 VULN 单独判定，不是全文数关键词：

| 维度 | 认可的同义写法 |
| --- | --- |
| 复现步骤 | 复现步骤 / 复现过程 / 复现路径 |
| 影响 | 影响 / 危害 / 业务影响 |
| 风险等级 | 风险等级 / CVSS / 等级 |
| 修复建议 | 修复建议 / 整改建议 / 修复方案 / 加固建议 |

**编号连续性**：VULN-NN 是否从 01 连续到 N，有没有断档或重号。

**敏感信息分级**：

| 级别 | 命中对象 | 处理 |
| --- | --- | --- |
| high | 公网 IP、域名、邮箱、手机号、密钥、私钥、JWT | 阻断发布 |
| medium | 私网 IP、回环地址、Windows/Unix 绝对路径 | 需确认后再发 |

**声明一致性**：把「22 个风险点」这类对外表述当独立断言，逐条在正文检索。找不到就报 conflict。它查的是口径不一致，不是报告写错。

## 实测

对一份 45 页、22 条发现的脱敏报告：

```
漏洞条目：22 条，编号 VULN-01 ~ VULN-22
结构完整：22/22
敏感信息：high 0 / medium 0
声明「22 个风险点」：冲突
声明「9 类」：冲突
```

前两项说明报告本身合格；后两项是真实的口径差异——报告写的是「22 条」和 8 个类型，对外材料写的是「22 个风险点、9 类」。工具把这个差异顶出来，改文案还是补报告由人决定。

## 测试

```bash
PYTHONPATH=src python -m unittest discover -s tests -t . -v
```

8 个用例，覆盖公网/私网分级、密钥与路径识别、脱敏掩码不误报、缺维度、编号断档、声明冲突。全部用合成文本，不引用真实目标数据。

## 局限

- 不判断漏洞真伪，也不给修复建议内容。
- 扫描件 PDF 没有文本层时直接报 `E_NO_TEXT_LAYER`，不做 OCR 猜测。
- 结构检查依赖「一条一个标题」的排版约定。报告如果把多条塞进一张表，切分不准。
- 同义词表是有限集合，字段名换了写法要补规则。
